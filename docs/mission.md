# Agent 能力工作台（Agent Workbench）— 项目立意

> 版本：v0.1（立项稿）· 2026-09-04 · 作者：张浩
> 项目地址：`~/Downloads/project/mine/personal-workbench/`

---

## 一、为什么做这个项目（痛点）

浩哥电脑上有大量 **skill 能力**和**实验性项目**，但它们是"沉睡资产"：

| 资产类型 | 现状 | 问题 |
|---------|------|------|
| **Hermes skills**（74 个）| 只能在聊天窗口里靠"触发词"唤起 | 不点开工作台就不知道有哪些能力；每次要用都开一段新对话 |
| **Claude skills**（llm-wiki、interview-workflow 等）| 散落在 `.claude/skills/` | 只有特定 agent 环境能调，Web 端完全不可达 |
| **实验性项目**（交易/漫剧/知识库仪表盘等）| 已聚合在工作台卡片 | 只有"启动/打开"，没有"能力对话"入口 |

**一句话**：能力存在，但没有一个统一的、Web 化的、可对话的入口把它们串起来。

---

## 二、项目定位（立意核心）

> **个人 Agent 能力工作台：让浩哥电脑上的每一个 skill 能力，都变成工作台里一个"点开就能对话"的应用。**

- 它是**壳**：不重新实现能力，只做编排、呈现、生命周期管理
- 它是**桥**：把 Hermes/Claude 两套 skill 体系统一到一个 Web 入口
- 它是**操作系统**：能力 = 应用（App），工作台 = 应用商店（Launcher + Runtime）

**对标**：个人电脑的 App Store + 控制台。所有自研能力像 App 一样安装、打开、对话、关闭。

---

## 三、愿景（长期）

1. **Phase 1（当前）**：工作台从"项目聚合器"升级为"能力聚合器"——每个 skill 一张卡片，点开进入对话页
2. **Phase 2**：对话页支持连续会话（session 续接）、历史记录、能力间跳转（消化完直接查图谱）
3. **Phase 3**：能力可组合——"消化文章 → 生成日报 → 推送 Obsidian"一条流水线可视化编排
4. **Phase 4**：多机同步（家里/公司），能力配置云端化

## 四、技术架构

```
┌─────────────────────────────────────────────────────────┐
│                    浏览器 (工作台 Web UI)                 │
│   卡片墙(能力/项目) · 对话页(流式输出) · 控制台(终端)      │
└──────────────────────────┬──────────────────────────────┘
                           │ HTTP / SSE
┌──────────────────────────┴──────────────────────────────┐
│              personal-workbench 后端 (FastAPI :8899)      │
│  /api/skills 能力清单 · /api/skill/run 启动对话            │
│  /api/skill/stream SSE 流式 · 子进程池 + 超时 + 并发控制    │
└──────────────────────────┬──────────────────────────────┘
                           │ spawn
┌──────────────────────────┴──────────────────────────────┐
│                   Hermes Agent CLI                        │
│   hermes chat -q <问题> --skills <skill> -Q               │
│   --resume <session_id> 续接会话                          │
└──────────────────────────┬──────────────────────────────┘
                           │ 加载
┌──────────────────────────┴──────────────────────────────┐
│   Skill 库（两套统一入口）                                 │
│   ~/.hermes/skills/        Hermes skills (74个)          │
│   ~/Downloads/笔记/笔记/.claude/skills/  Claude skills    │
│   （llm-wiki / interview-workflow 等，需桥接）            │
└─────────────────────────────────────────────────────────┘
```

**关键决策**：用 `hermes chat --skills <skill> -Q` 作为能力调用通道（已验证可行，返回 session_id 支持续聊），**工作台只做壳**——不碰 skill 内部逻辑，不重新实现 LLM 调用。

## 七、风险与对策

| 风险 | 对策 |
|------|------|
| `hermes chat` 每次冷启动慢（秒级）| 子进程池预热 + 只对长任务用 |
| 并发多 skill 对话 → 进程爆炸 | 全局信号量限流（默认 2 并发）|
| llm-wiki 是 Claude skill，Hermes 不识别 | 桥接层：把 `.claude/skills/llm-wiki` 软链/复制进 `~/.hermes/skills/`（已验证 --skills 只认后者）|
| 消化写 wiki 库（写操作风险）| 默认 dry-run 只读预览，确认后再写（沿用红线）|
| CLI 输出非结构化 | 统一包一层 JSON 封装（`--skills` 加载 + 结果截断 + 错误分类）|

## 八、开发规范（沿用浩哥红线）

- **工程规范**：Vue3 + Ant Design Vue + Pinia + Vite（已有），后端 FastAPI
- **只读优先**：能力入口默认只读；写操作（如消化落库）必须显式确认
- **不重复造轮子**：工作台只做壳，能力复用现有 skill/脚本
- **每个能力一个卡片**：卡片 = 名称 + 描述 + 状态 + 打开按钮
- **代码评审**：符合 code-review-expert 标准

---

## 九、验收定义（什么样的产品算"做成了"）

1. 打开个人工作台 → 看到「我的 Skill 能力」墙（自动扫出两套 skill 库）
2. 点「知识库」卡片 → 对话页里说"帮我消化这篇 <链接>" → 走完 llm-wiki ingest 流程
3. 点「面试」卡片 → 对话页说"筛选简历" → 走完 interview-workflow
4. 点「代码库」卡片 → 问 graphify → 返回架构分析
5. 对话可续接（关掉再开不丢上下文）
