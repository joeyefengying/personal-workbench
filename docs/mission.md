# Agent 能力工作台（Agent Workbench）— 项目立意

> 版本：v0.2（启动器模式）· 2026-09-04 · 作者：张浩
> 项目地址：`~/Downloads/project/mine/personal-workbench/`

## 一、为什么做这个项目（痛点）

浩哥电脑上有大量 **skill 能力**和**实验性项目**，但它们是"沉睡资产"：

| 资产类型 | 现状 | 问题 |
|---------|------|------|
| **Hermes skills**（74 个）| 只能在聊天窗口里靠"触发词"唤起 | 不点开工作台就不知道有哪些能力；每次要用都开一段新对话 |
| **Claude skills**（llm-wiki、interview-workflow 等）| 散落在 `.claude/skills/` | 只有特定 agent 环境能调，Web 端完全不可达 |
| **实验性项目**（交易/漫剧/知识库仪表盘等）| 已聚合在工作台卡片 | 只有"启动/打开"，没有"能力对话"入口 |

**一句话**：能力存在，但没有一个统一的、可一键唤起的入口把它们串起来。

---

## 二、项目定位（立意核心）

> **个人 Agent 能力工作台：让浩哥电脑上的每一个 skill 能力，都变成工作台里一张"点开就能对话"的卡片。**

- 它是**壳**：不重新实现能力，只做编排、呈现、唤起
- 它是**桥**：把 Hermes/Claude 两套 skill 体系统一到工作台入口
- **对话本体 = Hermes 原生**（多轮/记忆/流式/工具全复用，不重复造轮子）

**核心决策（v0.2 修正）**：~~Web 弹窗对话~~ → **启动器模式**。点卡片 → 原生 Terminal.app 拉起 `hermes chat --skills <skill>` 交互式对话。工作台只负责"打开对话"，不重新实现聊天 UI。

---

## 三、技术架构（v0.2）

```
┌─────────────────────────────────────────────────────────┐
│                    浏览器 (工作台 Web UI)                 │
│   卡片墙(能力/项目) · 点 skill → 弹确认 → 启动对话         │
└──────────────────────────┬──────────────────────────────┘
                           │ HTTP
┌──────────────────────────┴──────────────────────────────┐
│              personal-workbench 后端 (FastAPI :8899)      │
│  /api/skills 能力清单(扫描两套skill库) · /api/skill/open   │
└──────────────────────────┬──────────────────────────────┘
                           │ osascript / open
┌──────────────────────────┴──────────────────────────────┐
│               macOS Terminal.app (原生终端)               │
│   hermes chat --skills <skill>   ← 交互式对话本体          │
│   （多轮/记忆/流式/工具 全部 Hermes 原生）                 │
└─────────────────────────────────────────────────────────┘
```

**关键决策**：
- 对话**不在浏览器**，在原生终端 —— Hermes 的 TUI 本身就是最好的对话界面
- `--skills <slug>` 确保对应 skill 真正加载（llm-wiki/interview 等已软链桥接进 `~/.hermes/skills/`）
- 可选 `query` 参数预填首句（如"帮我消化这篇 <url>"）

## 七、风险与对策

| 风险 | 对策 |
|------|------|
| `hermes chat` 每次冷启动慢（秒级）| 子进程池预热 + 只对长任务用 |
| 并发多 skill 对话 → 进程爆炸 | 全局信号量限流（默认 2 并发）|
| llm-wiki 是 Claude skill，Hermes 不识别 | 桥接层：把 `.claude/skills/llm-wiki` 软链/复制进 `~/.hermes/skills/`（已验证 --skills 只认后者）|
| 消化写 wiki 库（写操作风险）| 默认 dry-run 只读预览，确认后再写（沿用红线）|
| CLI 输出非结构化 | 统一包一层 JSON 封装（`--skills` 加载 + 结果截断 + 错误分类）|

## 八、开发规范（沿用浩哥红线）

- **工程规范**：Vue3 + Ant Design Vue + Pinia + Vite（已有），后端 FastAPI
- **只读优先**：能力入口默认只读；写操作（如消化落库）必须显式确认
- **不重复造轮子**：工作台只做壳，能力复用现有 skill/脚本
- **每个能力一个卡片**：卡片 = 名称 + 描述 + 状态 + 打开按钮
- **代码评审**：符合 code-review-expert 标准

---

## 九、验收定义（什么样的产品算"做成了"）

1. 打开个人工作台 → 看到「我的 Skill 能力」墙（自动扫出两套 skill 库）
2. 点「知识库」卡片 → 弹出确认 → Terminal 打开 `hermes chat --skills llm-wiki`，能说"帮我消化这篇 <链接>" 走完 ingest 流程
3. 点「面试」卡片 → Terminal 打开 interview-workflow，能"筛选简历"
4. 点「代码库」卡片 → Terminal 打开 graphify，能问代码库
5. 对话多轮、记忆、流式全部是 Hermes 原生体验
