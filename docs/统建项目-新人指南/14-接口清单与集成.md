# 14 接口清单与集成：谁调谁、怎么幂等、失败怎么办

> **什么时候用得上**：联调排期、写接口对接方案、被问“这个字段从哪来”、上线前补失败补偿。<br>
> **最重要的前提**：**不存在平台级统一接口清单。** 实际形态是**每份详细设计文档各自带一个“6.2 集成接口清单”**，编号从 I_1 起、按文档内顺序重编 —— 所以同一个接口在不同文档里编号不同（“更新合同金额”在一处是 I_2、另一处是 I_6）。**跨文档拼接必须靠接口名称对齐，不能靠编号。**

还有一层现实：相当一部分清单只写 4 列（接口编号 / 名称 / 生产·消费 / 描述），**根本没有“协议”“触发时机”“异常处理”列**。所以下表的空格不是遗漏，是原文就没有。

**已写明的补偿规则**：「更新合同信息失败后，**应付结算单提交失败，可重新进行提交**」⇒ 合同回写是**阻断式失败 + 人工重提**，没有自动补偿。

> ⚠️ **「合同结算」作为独立外围系统：知识库完全无证据。** 检索到的合同接口都出现在应付暂估结算单、应收报账、收入成本结转报账单等**单据内部**。要确认这一路，得找集成架构组。

## 3 影像系统

| 接口 / 机制 | 约束 |
|---|---|
| **IF-09 附件上传（影像中心）** | 文件流上传；支持 PDF/OFD/JPG/PNG/Word/Excel/PPT；**单文件 ≤ 50M、单次 ≤ 50 个、重名拦截**；**返回附件 ID**，附件张数由平台计数 |

- **落库字段是双键**：业务单据表上并存 `file_id`（影像 id）与 `inst_file_id`（实例 id），另有 `inv_id`（发票 id）⇒ **影像与单据的关联是“影像ID + 实例ID”**，不是单纯附件清单。
- 上传来源多渠道：电脑文件、**票夹**、**扫描**、**高拍仪**、邮箱。部分单据口径更严：单次 ≤ 50 个文件、单个 10M；电子火车票/机票需上传 **OFD/XML 源文件**。
- **唯一一条“影像触发税务”链路**：对公费用报账单「本地上传票据」后**自动调税务识别查验接口**，识别成功后发票信息自动写入发票明细区域。

## 5 电子档案（异步归档 + 逐笔回执 + 可重推的最佳样板）

| 接口 | 方向 | 触发时机 | 状态 / 补偿 |
|---|---|---|---|
| **归档请求** | 业务系统 → 电子档案（API） | 生成版式文件后发**归档请求 + 归档元数据**；财务域内为「上传完成确认时自动推送」 | 未取到幂等键 |
| **档案状态查询** | 源头 → 电子档案（API） | 源头查询，**支持按批次批量查询** | 状态：**待接收 / 已检测 / 已归档** |

**接口边界（很重要）**：推送内容是「单据业务字段 + 版式文件与附件元数据（名称、大小、**SHA-256 哈希**、**文件存储 ID**）」，**接口不接收附件文件本体** —— 档案系统按文件存储 ID 到**文件中心**拉取。

**归档粒度**：按**会计凭证号与源头单据对应关系**，**一个会计凭证一件档案**；补充附件复用同一接口，档案系统**重新执行四性检测与业务规则校验**。

**处理链**：接收 → 文件复制归集 → **四性检测 + 业务规则检测** → 组卷、上架 → 入存储。

**反馈与补偿**（本清单里最具体的一处）：
- 实时响应、**按原批次反馈**；**按每一笔**（如固定资产卡片台账 guid）返回成功/失败，**失败附原因**；
- 校验逻辑：①必填字段为空 → **批量返回**；②**配置未维护**（全宗未匹配、档案类型未匹配、默认管理部门未匹配）→ 返回接收失败；
- 关键一句：**「处理后可再次推送」** ⇒ 失败补偿 = **源头系统重推**；
- 补充附件**只允许新增，不允许删除**；
- 档案侧可**退回电子档案 → 退回源系统**并记录退回意见。

## 7 幂等与失败补偿：能确认的 7 类，和完全空白的

| 机制 | 证据 |
|---|---|
| 接口级重复校验 | PTMS-001 校验「ERP 端付款唯一标识是否重复」 |
| 业务主键 + 重付追溯 | `bizBillId` 唯一码；重付填**前序原始单号** |
| 状态枚举防重 | 资金计划 `occupyStatus` 四态 |
| 有限重试 + 超次提示 | 合同信息获取「多次尝试，超过次数提示」 |
| 同步失败即阻断 | 合同更新失败 → 结算单提交失败 → 人工重提 |
| 逐笔回执 + 源头重推 | 档案系统逐笔反馈 + 「处理后可再次推送」 |
| 人工兜底 | 重新推送司库、标记成功/失败、付款结果查询 |

> ❌ **完全空白**的四项（必须补齐，否则联调时只能靠猜）：
> 1. **没有统一的重试/补偿规范** —— 重试次数默认值、退避策略、死信队列、补偿任务调度，全无。
> 2. **绝大多数接口的“异常处理”列原本就是空的**（4 列式清单结构缺列）。
> 3. **MQ 类异步接口**：只在个别文档标题出现「MQ 消费者」（如“凭证推送回执(mq消费者)”），**消息体格式、幂等键、重复消费规则全未取到**。
> 4. **影像/税务识别/主数据的幂等键未取到**（是用单据ID、发票ID 还是文件哈希，文档没写）。
