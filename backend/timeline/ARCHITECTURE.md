# 时间线数据架构 — 数据分层与保留策略

> 目的：时间线只做「汇总总结」，不做「数据椅子」（完整原始数据副本）。
> 原则：**采集够分析的最小集合，分层存储，过期清理，缓存可重建。**

## 一、数据分层

```
┌─────────────────────────────────────────────────────────────┐
│ Layer 3 · 汇总层 (summary)   — 永久保留, 体积最小            │
│   每日每域名访问次数 / 每项目提交数 / 每会话发言数            │
│   用途: 周报/月报/年报趋势, 耗时统计, 绩效                      │
├─────────────────────────────────────────────────────────────┤
│ Layer 2 · 事件层 (events)    — TTL 30天, 分析用            │
│   去重后的高价值事件 (今天访问了哪些域名/说了什么/改了什么)     │
│   用途: 日报生成, 近期活动回顾, Obsidian 关联                   │
├─────────────────────────────────────────────────────────────┤
│ Layer 1 · 原始层 (raw)       — 不落盘, 采完即弃             │
│   轻推全量消息 / Chrome 全量 URL / 文件快照                    │
│   用途: 采集瞬间的临时中间态, 用完即丢                         │
└─────────────────────────────────────────────────────────────┘
```

## 二、各渠道的「够用」定义

| 渠道 | 全量(不存) | 事件层(存30天) | 汇总层(永久) |
|------|-----------|---------------|-------------|
| 浏览器 | 每条 URL 访问 | **单日每域名去重**（今天访问了 github.com，而非 8 条 github URL） | 每日每域名访问次数 |
| 轻推 | 每条原始消息 | **我的高价值发言，跨会话去重**（同一转发消息只存一次） | 每日每会话发言数 + 主题分布 |
| Git | 每条 commit diff | 每次提交记录 | 每日每项目提交数 |
| 文件 | 每个文件变更 | 单文件单日首次变更 | 每日每目录变更数 |

## 三、去重键设计（dedup_key）

- **浏览器**: `browser|visit|{date}|{domain}` — 单日每域名只 1 条事件
- **轻推**: `qingtui|msg|{date}|{内容md5前16}` — 跨会话同内容只 1 条
- **Git**: `git|commit|{hash}` — 天然唯一
- **文件**: `files|{action}|{date}|{path}` — 单日同路径同动作只 1 条

## 四、保留策略（TTL）

| 层级 | 保留期 | 清理动作 |
|------|--------|---------|
| events 事件层 | 30 天 | 过期事件 → 删除（已聚合进 summary） |
| summary 汇总层 | 永久 | 不清理（体积极小，趋势分析依赖） |
| file_snapshot | 1 份（滚动覆盖） | 每次采集覆盖，不含历史 |

## 五、清理机制

1. **每次采集后**触发 `cleanup_events(ttl=30d)`，删除过期事件
2. **每次采集时**先 `aggregate_to_summary()`，把当天事件聚合进 summary 层
3. **VACUUM** 每周一次，回收 SQLite 空闲页

## 六、健壮性保障

- **幂等**: 所有采集器可重复运行，dedup_key 保证不重复入库
- **可重建**: summary 层可从 events 层重算；events 层可从源系统重新采集
- **限流**: 轻推采集并行度上限 4，避免打爆源系统
- **降级**: 某渠道失败不影响其他渠道，单独记录错误
